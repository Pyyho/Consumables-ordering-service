# Сервис заказа расходных материалов

Консольное приложение для ведения справочника расходных материалов и обработки
заявок сотрудников организации. В ПР3 функциональная модель проекта заменена
объектной: данные загружаются из JSON в связанные объекты, а перед сохранением
снова преобразуются в обычные структуры JSON.

## Возможности

- просмотр, поиск, добавление, изменение и удаление материалов;
- проверка складского остатка и сортировка материалов;
- просмотр, поиск и добавление сотрудников;
- создание заявки с выбором сотрудника и материала;
- фильтрация заявок по статусу, сотруднику и дате;
- изменение статуса, отмена заявки и просмотр истории;
- сохранение данных между запусками программы;
- обработка некорректного ввода и ошибок файлов.

## Объектная модель

### Material

Объект расходного материала.

- Атрибуты: `id`, `name`, `unit`, закрытый остаток `_stock`.
- Свойство: `stock` предоставляет безопасный доступ к остатку.
- Методы: `has_stock()`, `update()`, `from_data()`, `__str__()`.
- Статический метод `validate_stock()` проверяет корректность остатка.

### User и Employee

`User` хранит общие данные пользователя: `id`, `name`, `email`.
`Employee` наследуется от `User`, добавляет атрибут `department` и переопределяет
`__str__()`. Это показывает наследование и полиморфизм: функция вывода работает
с базовым типом `User`, а фактическое представление определяется классом объекта.

Основные методы: `validate_email()`, `from_data()`, `__str__()`.

### SupplyRequest

Объект заявки сотрудника на материал.

- Атрибуты: `id`, `employee`, `material`, `quantity`, `created`.
- Инкапсулированное состояние: `_status` и `_history`.
- Свойства: `status`, `history`, `is_cancelled`.
- Методы: `change_status()`, `cancel()`, `from_data()`, `__str__()`.

## Взаимодействие объектов

Каждая заявка хранит ссылки на существующие объекты `Employee` и `Material`:

```text
SupplyRequest
├── employee ──> Employee ──> User
└── material ──> Material
```

Программа работает с коллекциями `list[Material]`, `list[Employee]` и
`list[SupplyRequest]`. Функции модулей выполняют операции над коллекциями, а
поведение конкретного объекта реализовано его методами.

## Хранение данных

Данные находятся в каталоге `data`:

- `materials.json` — материалы;
- `employees.json` — сотрудники;
- `requests.json` — заявки.

В заявке JSON хранятся `employee_id` и `material_id`. При загрузке модуль
`storage.py` находит соответствующие объекты и передаёт их в `SupplyRequest`.
При сохранении объектные ссылки снова заменяются идентификаторами.

```text
Consumables-ordering-service/
├── main.py
├── materials.py
├── orders.py
├── users.py
├── storage.py
├── utils.py
├── models/
│   ├── __init__.py
│   ├── materials.py
│   ├── requests.py
│   └── users.py
├── data/
│   ├── materials.json

│   ├── test_materials.py
│   ├── test_requests.py
│   ├── test_storage.py
```

импортов ПР2 и перенаправляют их в пакет `models`.

## Требования и установка

Требуется Python 3.10 или новее. Основной код использует стандартную библиотеку.
Инструменты разработки устанавливаются командой:

```bash
python -m pip install -r requirements.txt
```

## Запуск приложения

```bash
python main.py
```

## Тестирование и проверка кода

```bash
pytest -v
flake8 . --exclude=.venv,.venv313,tmp
```

Тесты проверяют создание объектов, методы классов, наследование, взаимодействие
заявки с сотрудником и материалом, функции обработки коллекций, JSON-загрузку и
сохранение связанных объектов.
